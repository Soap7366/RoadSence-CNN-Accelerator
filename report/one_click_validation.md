## 卡住原因与处理

对用户卡住的真实进程抓取调用栈，工作线程位于 Paramiko packet.write_all → SFTP put。该循环可持续重试 socket timeout，原先的远程命令超时无法覆盖上传。旧流程还把已有部署检查的任何异常都当作部署损坏，网络超时会触发重传，且没有显示文件进度。

后续复现也观察到板端命令已退出而电脑仍等待 SSH 退出通知。现在有限远程命令带随机完成标识和真实返回码，并在板端原子发布完成回执。电脑每5秒通过独立通道回查，恢复已完成命令的返回码与日志，不重复执行命令；仍保留超时。

- 准备任务在独立子进程执行，GUI 显示阶段、用时、上传进度，支持取消整个进程树。
- 使用单个压缩包上传，完整 SHA256 读回后解压，再逐文件验证交付清单。
- 上传/读回连续30秒无活动时关闭 TCP 连接；父进程有无输出与阶段硬时限保护。
- 等待每5秒更新用时，网络超时不再触发重新部署。
- 已配置同网段的有线网卡不因短暂 SSH 超时而重新配网。
- 同一文件夹的 Prepare 使用进程锁，避免重复运行。
- 缺少 Python 时将官方签名验证后的 Python 安装到 .runtime/python312，不修改 PATH。

保持原目录结构。未修改 CNN、网络层、模型权重、量化、预处理、INT32计算、后处理、RTL或bit/HWH；每4帧取1帧和原帧率播放规则保持不变。

电脑网卡已能连接板卡，未在物理网卡上执行配网/UAC修改和恢复；只读发现、参数、已有网段分支已验证。确需配网时仍须用户完成管理员授权。程序适用于原参考 PYNQ 系统，不制作或替换SD系统。
