# 可复用工作流

## 适用条件与输出

适用：已有加速器或参考模型，需要联调、替换预处理、调整并行度或评估性能。输入至少包括目标接口合同和一组可追溯参考结果。输出为身份清单、正确性结论、按边界测量的性能及可复验命令。

失效条件：没有参考结果时不能声明数值正确；只有 mock 时不能声明上板通过；更换模型、图像库、板卡、镜像、量化参数后需要重验对应合同。DMA、浮点加速器和其他输入形状可复用方法，需要实现自己的输入输出检查。

## 正确性优先的步骤

1. 保存基线。列出原始文件 SHA256、工具版本和部署身份，记录当前未提交修改。不要仅凭文件夹版本号判断设备镜像。
2. 制定合同。输入形状/类型/布局、预处理顺序、舍入、量化范围；输出原始类型、缩放、单位；通信边界、完成条件、故障策略。
3. 固定一组样本。包含正常、边界、非法输入；保留重复输入，不用去重改变测量任务。
4. 先运行离线参考和字节比较，定位首次差异。预处理差异未解决前不把输出偏差归因于RTL。
5. 运行接口 mock，覆盖错误身份、乱序、截断、超时、复位与恢复。真实硬件复验必须单独列出。
6. 上板时核对镜像、地址、身份和独占状态。根据接口能力验证输入写入、回读、结果稳定性和序号。错误会话不当作成功会话续用。
7. 对比 raw 输出，再进行后处理；检查单位、符号与是否重复非线性变换。

## 性能诊断

| 测量对象 | 方法 | 不能推导的结论 |
|---|---|---|
| PL核心 | 硬件周期计数器，或清楚标明RTL仿真周期 | RTL周期不是当前板端实测 |
| PS控制事务 | 同一PS单调时钟分段 | 轮询完成包含调度和检测开销 |
| 输入上传 | 发送、收齐各自计时，记录字节数 | sendall耗时不是跨机单向网络时延 |
| 单图延迟 | 同一PC从发起到对应结果 | 批吞吐的倒数不是单图延迟 |
| 批吞吐 | 成功完成数量/明确的批次区间 | 并行阶段均值不能直接相加 |

先比较 reference/native，再比较 workers=1/2 或窗口大小。每次保留所有会话、首批与稳定批、错误与重传/CRC增量。CRC与长等待同时出现只支持链路排查，不能独立证明唯一根因。更换硬件资源或时钟需要重新实现、时序检查和板端验收。

## 迁移到另一题目或板卡

重新填写合同和 profile；替换 golden；实现目标接口的写入/结果完成检查；重新核对 bit/HWH、时钟和寄存器或DMA描述；对比一次离线结果和一次真实板端结果。交付报告应附迁移修改点和命令。此技能的方法不绑定板卡，但当前附带案例仅在 PYNQ-Z2 CNN 上有历史硬件证据，尚无第二板卡验证。
